# Orders Workspace presentation contract v1

Owner: DungeonQ core. Status: implemented synthetic research profile, not general cognitive-defense efficacy. Compatibility: opt-in `orders-workspace/v1`; default `disclosed/v1` remains supported.

- The existing deterministic world/store is authoritative. The projection supplies opaque world/epoch-bound handles, English workflow labels and persisted order records. It cannot add authority, rewrite historical effects or fabricate an origin readback.
- UI and MCP share the same projection and strict command validation. `choose` accepts one currently visible handle; `report` accepts explicit completion, confidence and concern. Unknown fields, unavailable handles, cross-world credentials and changed idempotency requests are rejected. An exact retry uses its historical revision and returns the original result.
- All records are synthetic and seed-derived. `basedOn` explicitly identifies derived evidence. Receipts preserve identity and content on revisits; a reader is admitted only after the first reconciliation. The credential retains the existing world/epoch scope even though the participant is not shown the evaluator's scope label.
- Installation manifest v2 pins seed, depth, presentation and pack digest. Existing v1 installations reopen only in their original disclosed presentation. Mismatch fails closed. No silent migration between research presentations is permitted.
- Actor has four bounded tools only. Owner approval, broker credential, protected-origin credential and Observer control are absent. Owner can inspect the underlying journal and the unchanged local incident/approval/readback chain. Models cannot approve their own effect.
- Network/body/time/command limits remain enforced. Uncertain UI operations retain the exact request identity for retry; there is no new-effect retry after an ambiguous result. Auth, unavailable state or projection failure cannot grant A access. No arbitrary URL, executable payload, scan or production target is accepted.
- Participant output uses `SYNTHETIC_ONLY`. Observer hypotheses remain historical internal labels: `origin-record-confirmed` is a completion-checkbox mapping and **must not be interpreted as a verbatim origin-belief assertion**. Always inspect the participant's final statement. Confidence/concern are self-reports, not inferred mental state.
- Acceptance: actual HTTP/MCP parity, restart and pin mismatch, first-read admission, retry, cross-world rejection, A credential rejection, local alert receipt, unapproved rotation denial, separately approved TLS rotation/readback and post-rotation world continuation. Recorded pilot verification additionally replays exact participant-visible observations.

Rollback: stop the opt-in instance and use the retained disclosed installation or v0.8 release. Never downgrade a live state file or restore a revoked credential. Same-host application/process separation is not OS/network/cloud isolation. Static Sites is an evidence viewer, not this server runtime.
