# Causal study lab: install, play and verify

DungeonQ v0.6.0 adds a finite, synthetic two-feature learning experiment alongside the existing governed assistant. Profile: `SYNTHETIC_CAUSAL_STUDY`; [contract v1](contracts/STUDY_V1.md). It needs no enterprise environment, API key, Docker or cloud account. Read the [results and limitations](STUDY_RESULTS.md) before interpreting any score.

The interactive study interface is currently in Traditional Chinese. This English guide includes the important labels. The public static site is an evidence explorer and browser rehearsal, **not this server-backed study or its independent Observer**.

## Start a new study

Use Node.js **24.15.0+**. From the unpacked source directory containing `package.json`:

```sh
npm ci --ignore-scripts
npm run study
```

The terminal prints the private data directory, participant (`參與者`) URL, researcher (`主持人`) URL, MCP endpoint and short-lived tokens. The launcher randomly assigns the condition and causal rule unless explicitly configured, then fixes them in this installation. Listeners bind only to `127.0.0.1`; no model is called.

Give a participant on the same machine only the participant URL. The researcher page and data directory reveal the answer. Do not give either to someone taking that study blind. Remote reviewers should install their own copy; this is not a public multi-user service. Do not expose the HTTP listeners or tokens through a tunnel.

## A two-minute reviewer route

After installation, this checks the interaction and evidence boundary, not participant efficacy:

1. Open the participant URL and retain **`UI_CHECK`**. Read the notice and explicitly accept it. Do not label an automated review as a human participant.
2. Choose one object. Each card shows two features. Save a success/failure/unknown prediction and a hypothesis before execution. Leave confidence and suspicion blank if unknown; blank means `null`, not zero.
3. Execute the saved choice, inspect the actual result and any world-local receipt, then record reflection separately. An earlier prediction cannot be rewritten after seeing the result.
4. Select withdrawal (`退出`) to stop and reveal the precommitted rule, or continue to completion. Open the researcher URL, refresh and replay, then download the evidence. The researcher can inspect the answer; the participant cannot access it before completion or withdrawal.

Verify the downloaded file:

```sh
npm run study:verify -- /absolute/path/to/downloaded-evidence.json
```

`valid: true` means the retained events can be regenerated by the fixed causal model. It does not certify identity, human presence, private thoughts, external timestamps or general LLM effectiveness. A short UI review is not another experimental subject.

## Complete participant flow

The protocol is **consent → predict → act → reflect**, repeated until completion. The consent notice states that clues can be incomplete, participation can stop, and existing local records remain. A person must choose `HUMAN_DECLARED` and consent for themselves; this declaration is not identity verification.

Only the saved object can be executed. Results follow the fixed rule; successful actions really update the local inventory and create receipts, but those receipts have no outside-world effect. Reflection records a hypothesis, optional confidence/suspicion, and next intention independently of the pre-action prediction. New forms start unknown rather than carrying forward the previous answer.

Refreshing reads the existing state without adding an event. After a timeout, use the interface's pending-request recovery control: it resends the original request ID and revision, not a new action. A pending request from another world must not be replayed. Withdrawal first resolves an uncertain prior request. A completed or withdrawn study does not reopen; use a new directory for a new participant.

## Researcher view and retained evidence

The researcher page separates predictions, results and post-result self-reports. It shows the assigned condition/rule, event count and first recorded high-confidence wrong hypothesis, diagnostic observation and high-suspicion report. These are event sequence numbers, not elapsed psychological time. No report means unknown, not a guessed belief.

The downloaded bundle includes the complete rule and condition. Do not disclose it to a participant before that study ends. There are no personal-information fields, but researchers remain responsible for handling records according to their participation agreement. Withdrawal retains earlier events; it is neither erasure nor permission to send them elsewhere.

The release preserves these original bundles without changing their bytes:

```sh
npm run study:verify -- evidence/study-v1/reference-correlated.json
npm run study:verify -- evidence/study-v1/reference-control.json
npm run study:verify -- evidence/study-v1/codex-pilot-a.json
npm run study:verify -- evidence/study-v1/codex-pilot-b.json
npm run study:verify -- evidence/study-v1/ui-check.json
npm run study:verify -- evidence/study-v1/ui-withdraw.json
```

The accompanying protocol, results, matrix and proof JSON files are reports, not replay-bundle inputs. The verifier rejects malformed input, altered events, causal mismatches, files over 2,000,000 bytes, invalid UTF-8 and symlinks.

## Supply an artificial design

Copy `study/designs/archive.json` or `study/designs/reviewer-garden.json` and edit artificial labels only:

```json
{
  "schemaVersion": "dungeonq.study-design/v1",
  "title": "Two-feature archive",
  "seed": 170926,
  "trainingRounds": 4,
  "probeBudget": 3,
  "labels": {
    "signalOn": "Amber mark",
    "signalOff": "Indigo mark",
    "structureOn": "Grooved",
    "structureOff": "Smooth"
  }
}
```

```sh
npm run study -- --design study/designs/reviewer-garden.json
```

The seed is an integer from 0 through 2147483647. Training allows 2–8 rounds, the probe budget 1–5. The four bounded labels must differ; the entire JSON is limited to 128 KiB. Code, URLs, credential-like strings, additional fields and unknown versions are rejected. This is a bounded two-feature design, not an arbitrary-world language.

On first initialization only, the researcher may choose `--arm CORRELATED` or `--arm DISCRIMINATING`, and `--rule signal` or `--rule structure`. The seed controls presentation order, not a publicly recoverable secret assignment. A blind participant should not receive initialization parameters or inspect the implementation/design internals.

## Stop, resume and protect data

Ctrl+C stops the lab and preserves data. Resume with the exact data directory printed at startup:

```sh
npm run study -- --data-dir /absolute/path/to/previous-study-directory
```

For a custom design, also supply the same `--design`. The saved manifest retains the assignment; repeating `--arm` and `--rule` is unnecessary. A different design or assignment is rejected rather than overwriting the study. Tokens change after restart: use the new URLs.

The directory must be private, mode 0700, and not a symlink; its manifest is mode 0600. It contains `study-installation.json`, `study.sqlite`, `study-observer.sqlite` and SQLite sidecar files. Keep it out of Git and release archives. To back up, stop normally and protect a copy of the **whole dedicated directory**. Do not copy just a live database or delete records to hide an unfavorable result.

The Observer is another process with another SQLite database. It replays events and acknowledges retained sequence/digest pairs; interrupted delivery can catch up. A bounded backlog stops ordinary new commands while reserving withdrawal capacity. If the entire service is unavailable, stop answering or close the page and confirm withdrawal after recovery; an unrecorded withdrawal must not be described as saved.

Process/role separation on one host is **not an OS-administrator sandbox**, independently controlled cloud account, notarized store or hardware trust root. Observer lag is relative to its latest received notification, not proof it has every event occurring now. A natural study has at most 46 study events / 15 world actions; this is not a scale benchmark.

## MCP and repeatable engineering checks

The official SDK 1.30.0 serves MCP **2025-11-25 Streamable HTTP**. Use the printed MCP endpoint and its dedicated Bearer token, not an Actor or Observer token.

- `dungeonq_study_view` returns the current participant projection.
- `dungeonq_study_act` accepts `{requestId,expectedRevision,command}` under the [phase contract](contracts/STUDY_V1.md).

The tools cannot select arbitrary targets, execute shell/code, reveal an unfinished assignment or change the conditions. UI and MCP share the same store/core; tool annotations do not enforce authorization. This server-side adapter does not modify the older browser WebMCP entry.

```sh
npm run test:study
npm run study:proof
npm run check
```

`study:proof` runs two real local studies, alternates HTTP and official MCP client commands, compares Observer and core evidence, and retains a matrix of 48 reference-learner conditions. It creates a new private output directory; optional `--out NEW_DIRECTORY` refuses an existing destination. It makes no model API calls and does not reproduce the Codex pilot or a human experiment.

`npm run world` and `npm run amazon` remain separate experiences with separate data. Stop the study launcher to stop this feature; retain its data for replay. Do not use an older binary to rewrite newer records.
